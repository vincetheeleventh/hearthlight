# D-023 · A skill that restates another skill's law is worse than no skill

**Date:** 2026-08-05 · **Source:** Vince, this session · **Agent:** cowork

**Context:** Vince asked for sheet creation to become its own skill. `hearthlight-asset-sheets` was
written, claiming a boundary of *who* (`hearthlight-character`) / *what*
(`hearthlight-mise-en-scene`) / *how* (the new skill). He then asked whether the separation was
necessary. It was audited the same day, by the agent that wrote it —
`governance/audits/2026-08-05-asset-sheets-boundary.md`.

**Reason:** The audit found four laws now stated in two places each — the lighting-neutral sheet, no
text on a sheet, immutability of approved files, and the catch-light criterion — plus the
no-double-pass law duplicated between the new skill and a video-prompts reference written **an hour
apart by the same author.**

That fails `GOALS.md` § Keeping features tight, criterion 1: *does it strengthen the single source of
truth, or create a second place where the same fact can be stated and diverge?* If duplication
appears that fast under one author, it appears faster across three agents.

The stated boundary sounded clean and was not. **Splitting *who a character is* from *how their sheet
is made* means two files must stay in agreement about one PNG.** The seam that actually holds is
different: per-asset-type craft belongs to the skill that owns that asset type; only laws true of
*every* asset are cross-cutting.

Vince chose distribution over shrinking the skill.

**Consequences:**

- `hearthlight-asset-sheets` deleted. The homeless material was distributed to its natural owners:
  - **`hearthlight-conventions`** — state splitting, the tag dictionary, and **the ten-out-of-ten
    asset stress test**. This skill already owned naming, the reference manifest, versioning and the
    gate protocol; an asset gate belongs with the other gates.
  - **`hearthlight-mise-en-scene`** — location sheet craft: 3/4 not frontal, the physical anchor, one
    light logic, and reverse angles including the empty-room video-walk technique.
  - **`hearthlight-character`** — believable-over-beautiful and the catch-light hard-reject.
  - **`hearthlight-image-prompts`** — the no-double-pass law: amend by mask, never by regeneration.
    Removed from `prompt-architecture.md`, which is about prompts, not images.
- Verified after: every one of those laws now appears in exactly **one** file.
- The cost Vince accepted: an agent building a location sheet reads two skills rather than one.
  The benefit: nothing to keep in sync.

**The general rule, which is the point of this entry:**

> Before creating a skill, ask what law it will state that no existing skill states. If the answer is
> "it restates several and adds a few", it is not a skill — it is a **reference or a distribution**.
> Conceptual tidiness for a reader is not worth a second place for a law to live.

**Caveat worth keeping:** the deleted skill was a reasonable idea badly bounded, not a bad idea. The
material it collected was real and is now in force. A future agent finding these rules scattered
across four skills should read this entry before proposing to gather them back up.
