# D-020 · Krea Stage-A prose contains only the visible shot

**Date:** 2026-08-05 · **Source:** Vince · **Agent:** chatgpt

**Context:** D-019 correctly assigned prompt judgment to a focused LLM author and grounding to
Python, but its renderer still appended a deliverable/aspect header, the locked style sentence, and
a `Must show` annex. The annex repeated the body; the style and aspect duplicated controls already
carried by Krea's moodboard and request packet. A valid structured object therefore became a less
coherent provider prompt.

**Reason:** Krea Stage A needs one readable spatial description. Aspect ratio is an API parameter;
style is conditioned by the selected moodboard and strength; required and forbidden elements are
compiler/reviewer checks. Re-emitting those layers in prose increases semantic load without adding a
new visible relationship.

**Consequences:** The focused LLM author writes the complete final Krea prompt body. It establishes
the whole relational tableau before atomic subject clauses, states each visible fact once, and ends
with shot-specific light or visual relationship. Python validates grounding, visibility, ownership,
one-instant state, coherence flags, and control separation, but appends no prose. Aspect, model,
moodboard, style strength, and acceptance checks remain structured request metadata. The independent
LLM reviewer blocks checklist repetition, style/control leakage, and attribute lists that fail to
establish a coherent shared space. Existing immutable prompt batches remain historical evidence;
new compilation creates new versions.

This supersedes D-019 while retaining its LLM-author/Python-validator/independent-reviewer division.
