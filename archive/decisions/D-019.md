# D-019 · LLM judgment writes prompts; code grounds and checks them

**Date:** 2026-08-04 · **Source:** Vince · **Agent:** chatgpt

**Context:** The first Shot Vision compiler had the correct source hierarchy and visibility object,
but its author received only a thin embedded rule paragraph. Python then assembled the final prose
mechanically. Most researched prompt craft—visual-system separation, atomic ownership, medium
translation, semantic-density control, continuity reasoning, and model-aware phrasing—was present as
documentation rather than active author context. No independent intelligent reviewer checked a
mechanically valid prompt for visual coherence.

**Reason:** High-quality prompting is a judgment task constrained by facts. An LLM is better at
translating intention into observable staging, selecting useful detail, resolving language, and
writing coherent provider prose. Python is better at exact retrieval, hashes, visibility regions,
counts, schema, forbidden leakage, provider controls, deterministic fixed text, and spend gates.
Neither should impersonate the other.

**Consequences:** Each Stage-A shot is handled by a focused, tool-restricted Hermes Shot Prompt
Author using `references/PROMPT-AUTHOR.md`. It receives one source bundle and writes both a structured
production object and `prompt_body`. Python validates grounding and invariants, adds the fixed
header and locked style sentence, and fingerprints the request. A separate tool-restricted Hermes
reviewer checks semantic coherence, source fidelity, continuity, attribute binding, medium language,
and Krea readability. One source-preserving repair is allowed; a second failure remains blocked.
The reviewer never invents direction, and no result bypasses Vince's exact Prompt Board approval.
This supersedes only D-018's allocation of final prose to a deterministic renderer; D-018's Shot
Vision authority, production-object, frame-one, visibility, and approval laws remain in force.
