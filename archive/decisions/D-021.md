# D-021 · Code moves by git; creative work moves by Syncthing

**Date:** 2026-08-05 · **Source:** Vince, this session · **Agent:** cowork

**Context:** Vince wants to run Hearthlight and the Film Study Tool on a MacBook as well as the
Windows machine. Both toolchains proved portable — every `os.name == "nt"` branch already had a
`darwin` counterpart, dependencies are Python ≥3.10, Pillow, and ffmpeg, and both servers are stdlib
`http.server`. The blocker was never the code. It was that **neither repository contains the work**:
Hearthlight excludes `projects/` (D-006) and the Film Study Tool excludes `data/` and `outputs/`.
A clone on a second machine yields both toolchains and zero films.

**Reason:** The content splits cleanly along a line that makes the decision for us. Measured
2026-08-05 across `projects/`: **311 files / 79 MB** are live creative work that changes constantly —
outlines, bibles, storyboards, generated stills, gate ledgers. **15 files / 4.31 GB** are raw source
media that never changes. `yugioh`, the v1 film, is 66 MB and entirely generated with no source at
all.

Syncing only the live set makes the problem small. Syncthing was chosen over the alternatives because
it is peer-to-peer with no cloud quota and no file-size ceiling, and because the McConaughey source
footage is **private use only** — putting it in a cloud account or a git remote, even a private one,
is a rights exposure with no upside. `00-source/**` is excluded by ignore rule rather than by
discipline, so it cannot leak by accident.

Git was rejected for the creative work: it would defeat D-006, and generated PNGs bloat history fast.
OneDrive was rejected for Story Studio because relocating it out of `AppData\Local` would break every
hardcoded path in the skills and pointer stubs.

**Consequences:**

- **Two sync folders.** `hearthlight-projects` (79 MB) and `film-study-outputs` (291 MB). Ignore
  rules are committed at `projects/.stignore` and `outputs/.stignore` so both machines share them.
- **370 MB moves, 5.6 GB stays.** Source media is carried by hand once, if ever.
- **The Story Studio root is now resolved per-OS** — `%LOCALAPPDATA%` on Windows,
  `~/Library/Application Support` on macOS, `$XDG_DATA_HOME` on Linux — with
  `HEARTHLIGHT_STUDIO_ROOT` overriding. Previously the macOS fallback silently resolved to the repo
  directory.
- **macOS launchers** live at `scripts/launch_studio.sh` with two thin `.command` wrappers, plus
  `start-dashboard.command` in Story Studio. The `.ps1` launchers stay for Windows.
- **A live conflict to resolve:** the Film Study Tool sits inside OneDrive on Windows. Running
  OneDrive and Syncthing over the same files causes conflict storms. One of them must be switched
  off for that folder.
- **`.env` never syncs.** Two copies, maintained by hand, deliberately.
- **`hermes` on macOS is unverified.** Without it the UIs run but Telegram gate approvals and
  `production_generation_worker.py` fail. This is the one open risk in the port.

Full setup path: `PORTING.md` in the Film Study Tool repository.
